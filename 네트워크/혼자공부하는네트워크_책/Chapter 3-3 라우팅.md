
## 라우팅, 라우팅 테이블

- **라우팅(Routing)**: 패킷이 출발지에서 수신지까지 도달하기 위해 거쳐갈 경로를 결정하는 과정.
- **라우팅 테이블(Routing Table)**: 라우터가 "이 목적지면 어디로 보낼지" 판단하기 위해 참조하는 표. 라우터마다 자체 보유.

# 라우터

네트워크 계층(L3) 장비. 서로 다른 네트워크를 연결하고, 패킷의 목적지 IP를 보고 다음 홉으로 전달.

- **L3 스위치**: L3에서 동작하면서 스위칭 기능까지 수행. 라우터보다 처리 속도 빠르고 기능 단순. 보통 LAN 내부 VLAN 간 라우팅용.
- **홉(Hop)**: 패킷이 라우터 하나를 거치는 단위. "3홉" = 라우터 3개 경유.
- 패킷은 여러 홉을 거쳐 다른 네트워크 내의 호스트로 이동 가능. 각 라우터는 자기 라우팅 테이블만 보고 **다음 홉만** 결정 → 분산적 의사결정.

# 라우팅 테이블

라우팅 테이블 한 줄을 풀어 읽으면:

```
"10.0.5.0/24 가려면 → eth0 포트로 → 192.168.1.1 에게 넘겨 → 비용 10"
    목적지          인터페이스        게이트웨이(next hop)     메트릭
```

### 수신지 IP 주소와 서브넷 마스크
- 어떤 네트워크 대역인지 식별. 예: `192.168.1.0/24`.
- 라우터는 들어온 패킷의 목적지 IP가 어느 대역에 속하는지 매칭(롱기스트 프리픽스 매치)해서 해당 행 선택.

### 다음 홉, 게이트웨이
- **의미**: 패킷을 그 네트워크로 보내기 위해 넘겨줄 **다음 라우터의 IP**.
- **왜 필요**: 라우터는 목적지까지의 전체 경로를 모름. 딱 다음 홉만 알고 그 다음은 다음 라우터가 결정 → 분산 라우팅 원칙.
- 목적지 IP는 패킷 헤더에 그대로 유지되지만, **L2 프레임의 목적지 MAC은 next hop의 MAC**으로 매번 바뀜 (ARP로 next hop MAC 조회).
- 직접 연결된 네트워크면 next hop 없음 ("on-link", 직접 ARP).

### 네트워크 인터페이스

- **의미**: 호스트/라우터가 네트워크에 연결되기 위한 **출입구(접점)**. 패킷이 들어오고 나가는 통로.
- 인터페이스 = 그 호스트가 **특정 네트워크에 대해 가지는 정체성 단위**. 인터페이스가 2개면 두 네트워크에 각각 다른 정체성으로 참여.

**유형**
- **물리 인터페이스**: 실제 NIC/포트. 케이블 꽂는 곳. 예: `eth0`(유선), `wlan0`(무선), `enp0s3`.
- **가상 인터페이스**: 소프트웨어로 만든 인터페이스. 예:
  - `lo` (loopback, 127.0.0.1) — 자기 자신과 통신
  - `tun0`, `tap0` — VPN
  - `docker0`, `veth*` — 컨테이너 네트워크
  - VLAN 서브 인터페이스 (`eth0.10`)

**인터페이스가 가지는 것 (자기 신분증)**
- MAC 주소 (L2 식별자)
- IP 주소 (L3 식별자) — 부여 안 될 수도 있음
- 상태 (up/down)
- MTU (최대 전송 단위)

**라우팅 테이블에 왜 명시되나**
- 라우터는 인터페이스가 여러 개이고, 각 인터페이스가 서로 다른 네트워크에 연결됨.
  ```
          [eth0] ─── 192.168.1.0/24 (사내망)
  라우터 ─ [eth1] ─── 10.0.0.0/24    (DMZ)
          [eth2] ─── ISP             (인터넷)
  ```
- next hop IP만으로는 부족 → **어느 포트로 내보낼지**까지 알아야 함.
- 인터페이스별로 ARP 테이블, MAC, VLAN, MTU가 다르므로 같은 next hop이라도 어느 인터페이스로 나가느냐에 따라 결과가 달라짐.

**확인 명령어**
```bash
# Linux
ip addr           # 모든 인터페이스와 IP
ip link           # 인터페이스 상태

# Windows
ipconfig /all
```

**호스트 vs 라우터**
- 일반 PC: 보통 인터페이스 1~2개(유선+무선). 라우팅 테이블도 단순.
- 라우터: 인터페이스 다수. 각 인터페이스가 다른 네트워크의 게이트웨이 역할 → 라우팅 테이블에서 인터페이스 명시가 필수.

### 메트릭
- **의미**: 경로의 비용/우선순위. **작을수록 좋은 경로**.
- **왜 필요**: 같은 목적지로 가는 경로가 여러 개 있을 수 있음(이중화, 백업 회선). 라우터가 그중 하나를 선택할 비교 기준이 필요함.
- 산정 방식은 프로토콜마다 다름:
  | 프로토콜 | 메트릭 |
  |---|---|
  | RIP | 홉 수 |
  | OSPF | 대역폭 기반 cost (`10^8 / bandwidth`) |
  | EIGRP | 대역폭 + 지연 등 복합 |
  | 정적 라우팅 | 관리자가 수동 지정 |
- 활용: 주 경로 메트릭 10, 백업 100 → 평소엔 주 경로, 장애 시 백업으로 전환(failover). 같은 메트릭 다중 경로면 ECMP로 분산.

### 디폴트 라우트(기본 경로), 0.0.0.0/0
- 라우팅 테이블에 매칭되는 항목이 없을 때 보내는 "기본 경로".
- 가정/사무실 PC는 보통 디폴트 라우트만 가지고 모든 외부 트래픽을 게이트웨이 라우터로 전송.

### route print 명령어
- Windows에서 라우팅 테이블 조회 명령. (Linux/macOS: `ip route`, `netstat -rn`)

# 정적 라우팅과 동적 라우팅

라우팅 테이블을 **만드는 방법**에 따른 분류.

### 정적 라우팅: 수동
- 관리자가 수동으로 경로 등록.
- 장점: 단순, 예측 가능, 오버헤드 없음.
- 단점: 망 변화(링크 장애 등) 자동 반영 불가. 규모가 커지면 관리 부담 폭증.

### 동적 라우팅: 자동, 수시 변환
- 라우터들이 라우팅 프로토콜로 정보를 교환 → 라우팅 테이블이 자동 생성·갱신됨.
- 장애나 토폴로지 변경에 자동 적응.

- **AS (Autonomous System, 자율 시스템)**: 동일한 라우팅 정책 하에 운영되는 라우터들의 네트워크 (예: 한 ISP, 한 기업망). AS마다 고유 번호(ASN)가 부여됨.

# 라우팅 프로토콜

AS를 기준으로 라우팅 프로토콜을 분류.

### AS 내부 수행 / 외부 수행
- **내부: IGP (Interior Gateway Protocol)** — AS 내부 라우팅. 예: RIP, OSPF.
- **외부: EGP (Exterior Gateway Protocol)** — AS 간 라우팅. 예: BGP.

### IGP - RIP, OSPF / 거리 벡터 ↔ 링크 상태

**거리 벡터 (Distance Vector) — RIP**
- 각 라우터가 "어느 목적지까지 몇 홉"이라는 거리 정보를 인접 라우터끼리만 교환.
- **RIP (Routing Information Protocol)**: 메트릭 = 홉 수. 최대 15홉(16은 도달 불가). 소규모 망에 적합.
- 단점: 수렴 느림, count-to-infinity 문제.

**링크 상태 (Link State) — OSPF**
- 각 라우터가 자기 링크 상태(인접 이웃, 비용)를 전 영역에 **플러딩** → 모두가 동일한 네트워크 지도를 가짐 → 다익스트라로 최단 경로 계산.
- **OSPF (Open Shortest Path First)**: 대표 링크 상태 프로토콜. 메트릭 = 대역폭 기반 cost. 수렴 빠르고 대규모 망에 적합.

### 링크 상태 데이터베이스 (LSDB)

**LSDB = Link State Database = "링크 상태 데이터베이스"**.

- 한 줄로: 영역 내 라우터들이 서로 알린 "내 링크 상태" 정보를 모아둔 저장소. = 네트워크 전체의 **토폴로지 DB**.
- 토폴로지 = 누가 누구와 어떻게 연결되어 있는지의 구조. 그 지도를 데이터로 저장한 것이 토폴로지 DB.

**저장 단위: LSA (Link State Advertisement)**
- 라우터 한 대가 광고하는 "나의 링크 정보" 한 조각.
- 내용: 나는 R1 / 내 이웃: R2(비용 10), R3(비용 5) / 링크 up·down.
- **LSDB = LSA들의 모음**.

**만들어지는 과정**
1. 각 라우터가 자기 LSA 생성
2. 이웃에게 전송 → 이웃이 또 자기 이웃에게 전달 (**플러딩**)
3. 영역 내 모든 라우터가 모든 LSA 수신
4. 각자 LSDB에 저장 → **영역 내 LSDB는 다 동일**

**예시**
```
     R1 ---10--- R2
     |           |
     5           20
     |           |
     R3 ---15--- R4
```
```
LSDB
├─ LSA from R1: 이웃 R2(10), R3(5)
├─ LSA from R2: 이웃 R1(10), R4(20)
├─ LSA from R3: 이웃 R1(5),  R4(15)
└─ LSA from R4: 이웃 R2(20), R3(15)
```
이걸 합치면 네트워크 전체 그래프 복원 → 다익스트라 돌려 최단 경로 계산 → 라우팅 테이블 생성.

**LSDB vs 라우팅 테이블**
| | LSDB | 라우팅 테이블 |
|---|---|---|
| 담는 것 | 전체 토폴로지 (원본 raw) | 목적지별 최적 경로 (계산 결과) |
| 영역 내 동일? | 동일 | 라우터마다 다름 (자기 기준 최단) |
| 용도 | 다익스트라 입력 | 패킷 포워딩 |

LSDB = 재료, 라우팅 테이블 = 요리 결과.

### Area 내에서의 링크 상태 공유
- OSPF에서 AS를 더 잘게 쪼갠 단위가 **Area**.
- 링크 상태 공유는 **영역(area) 내에서만** 일어남 → LSDB 크기 폭발 방지, 확장성 확보.
- 다른 area로는 요약된 경로 정보만 전달.

### Area Border Router (ABR)
- 두 area에 동시에 속해 area 간 라우팅 정보를 요약·전달하는 라우터.
- 보통 `Area 0`(백본 area)을 거쳐 다른 area와 통신.

### EGP - BGP

**BGP (Border Gateway Protocol)**: 인터넷의 AS 간 라우팅을 책임지는 사실상 유일한 프로토콜. TCP 179번 위에서 동작.

### eBGP, iBGP
- **eBGP (external BGP)**: 서로 다른 AS의 라우터끼리 맺는 세션.
- **iBGP (internal BGP)**: 같은 AS 내부 BGP 라우터끼리 외부에서 학습한 경로를 공유하기 위한 세션.

### 피어, 피어링
- **피어(Peer)**: BGP 세션을 맺은 상대 라우터.
- **피어링(Peering)**: AS끼리 BGP 세션을 맺고 경로 정보를 교환하는 행위/계약.

### AS_PATH, NEXT_HOP, Local-PREF

| 속성 | 의미 |
|---|---|
| **AS_PATH** | 목적지까지 거쳐가는 AS 번호 리스트. 짧을수록 선호. 자기 AS 번호가 보이면 무시 → 루프 방지. |
| **NEXT_HOP** | 해당 경로로 가기 위한 다음 홉 IP. |
| **LOCAL_PREF** | AS 내부에서 외부로 나가는 경로 중 어느 쪽을 선호할지. 값이 클수록 선호. iBGP로만 전파. |

### eBGP의 특징
- BGP는 AS 간 라우팅을 할 때 거치게 되는 **라우터의 수가 아닌 AS의 수**를 고려.
- BGP는 RIP처럼 단순히 수신지에 이르는 거리가 아닌 **메시지가 어디를 거쳐 어디로 이동하는지의 경로**를 고려 → 그래서 **Path Vector 프로토콜**이라 불림.
- 메트릭이 단순 거리가 아니라 AS_PATH, LOCAL_PREF, MED 등 다중 속성 기반의 **정책 라우팅**이 가능. 예: 특정 ISP를 일부러 우회.

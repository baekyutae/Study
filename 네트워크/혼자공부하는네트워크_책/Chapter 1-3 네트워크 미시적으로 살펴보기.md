
# 프로토콜

네트워크간에 정보를 올바르게 주고 받기 위해 합의된 규칙이나 방법

=> 택배 내용물과 송장을 송신자 전달자 수신자 모두 이해를 해야 정상적으로 택배가 보내지고 받아 내용을 확인 할수 있음<br>
ip, arp, https, tcp/udp 등이 프로토콜에 해당, 각자 저마다의 목적과 특징이 존재

# 네트워크 참조 모델

네트워크를 주고 받을 때 정형화된 여러 단계를 거치는데 이 과정을 계층적으로 표현한 것 == 네트워크 계층 모델<br>
이렇게 나누는 이유<br>
1. 네트워크 구성과 설계에 용이: 계층의 목적에 맞게 프로토콜과 네트워크 장비를 구성, 단 모든 장비가 각 계층에 1대1로 대응되지 않음(여러 계층을 포괄 하는 경우)
2. 네트워크 문제 진단과 해결에 용이: 각계층 별로 순차적으로 진단 <br>
네트워크 참조 모델이나 특정 계층은 네트워크를 작동시키는 주체가 아니다. 작동주체는 통신이 일어나는 단계를 역할별로 구획한 그림(=모델), 작동주체는 네트워크 장비
## 대표적인 네트워크 참조모델

OSI 모델: 7계층으로 구성 
1) 물리: 비트 신호 주고받음
2) 데이터 링크: 주변 장치간에 데이터 전송
3) 네트워크: 네트워크 간의 통신
4) 전송: 패킷 흐름 제어, 전송 오류 점검 => 신뢰성 보장
5) 세션: 호스트의 응용프로그램 간 연결 상태 생성 및 유지, 종료 
6) 표현: 압축, 암호화, 컴퓨터가 이해 가능한 코드로 변환
7) 응용: 사용자가 이용할 응용프로그램에 다양한 네트워크 서비스 제공<br>

TCP/IP 모델: 구현에 중점을 둔 네트워크 참조 모델, 여기서 IP는 Internet Protocol의 약자
1) 네트워크 액세스 계층: OSI 모델의 데이터 링크 계층과 유사,물리계층과 데이터 링크 계층으로 나눠 보기도 함
2) 인터넷 계층: OSI에서의 네트워크 계층과 유사
3) 전송계층
4) 응용계층: OSI에서의 세션,표현,응용계층을 합친 것과 유사

# 캡슐화와 역캡슐화<br>
패킷 송신 과정에서 캡슐화가, 수신과정에서 역캡슐화가 발생

## 캡슐화

패킷 교환 네트워크에서 메세지는 패킷 단위로 송수신
어떤 정보를 송신할 때 각 계층에서 상위 계층으로 부터 내려 받은 패킷을 페이로드 삼아 프로토콜에 걸맞는 헤더(or 트레일러)를 덧붙인 후 하위 계층으로 전달
encapsulation이라 함<br>
## 역캡슐화

수신하는 과정에서 역으로 상위 계층으로 이동하며 캡슐화 과정에서 붙였던 헤더와 트레일러를 각 계층에서 확인 후 제거,
받은 택배를  송장 떼고 포장을 벗기는 과정과 유사

# PDU
각 계층에서 송수신되는 메세지의 단위를 Protocol Data Unit(PDU)라 한다.<br>
OSI 7계층기준으로 보면

응용,표현,세션: data
전송: segmant, datagram
네트워크: packet
데이터링크: frame
물리: bit<br>
전송계층에서 프로토콜이 tcp인 경우 segmant, udp이면 datagram이 됨<br>
차이점으론
TCP는 연결 지향적이며 신뢰성을 최우선으로 한다. 'segmant'라는 명칭은 큰 데이터를 적절한 크기로 '분할(Segmentation)'하고, 각 조각에 번호를 매겨 관리한다는 의미가 강함<br>
UDP는 비연결형이며 효율성과 속도를 최우선으로 한다. 'datagram'은 독립적인 데이터 단위라는 뜻으로, 앞에 보낸 데이터와 뒤에 보낸 데이터 사이에 아무런 관계가 없음을 의미한다.

# 트래픽과 네트워크 성능 지표

트래픽은 네트워크 내의 정보량을 의미

통신 매체를 도로, 통신 매체에 흐르는 데이터를 자동차라 했을때 자동차수에 해당<br>
처리율, 대역폭, 패킷 손실 3가지 요소로 성능 지표를 삼음<br>
## 처리율(throughput)<br>
단위 시간당 네트워크를 통해 실제로 전송되는 정보량, bit, Mbps, Gbps 단위로 표현 또는 초당 패킷수(pps)를 사용<br>
실시간성이 강조된 지표로 특정 노드가 얼마만큼의 트래픽을 처리하는 중인지 판단 기준<br>
## 대역폭(bandwith)<br>
단위 시간동안 통신 매체를 통해 송수신 할수 있는 최대 정보량, bit, Mbps, Gbps 단위로 표현<br>
## 패킷 손실(packet loss)<br>
송수신되는 패킷이 손실된 상황, 높은 트래픽으로 인해 노드가 처리해야할 패킷이 너무 많거나, 네트워크 장애로 인해 패킷 처리를 못하면 손실이 발생할 수 있다.
전체 패킷중 손실된 패킷 비율을 백분위로 표현

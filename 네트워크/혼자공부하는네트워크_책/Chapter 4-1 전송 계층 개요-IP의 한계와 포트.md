
# 신뢰할 수 없는 통신과 비연결형 통신 

네트워크 계층의 핵심 프로토콜인 ip는 비신뢰성과, 비연결형 통신이란 한계이자 특징을 가짐<br>
- 신뢰할 수 없는 통신: ip프로토콜이 패킷이 수신지까지 제대로 전송되었단 보장을 하지 않는 특징
- 비연결형 통신: 송수신 호스트 간에 사전 연결 수립 작업을 거치지 않음<br>
왜 이런 특징을 가질까?
성능상의 이유 때문이다. 패킷이 제대로 전송되었는지 여부를 확인하고 송수신 호스트간에 연결을 수립하는 작업이 빠른 송수신과는 배치되는 작업이다

또한 금융과 같이 신뢰성이 매우 중요한 특정 경우를 제외하곤 패킷이 일부 손실되더라도 서비스 제공에 크게 지장이 발생하지 않으며 오히려 빠른 전송이 더 중요시 되기도 한다(ex 스트리밍 서비스)


# IP의 한계를 보완하는 전송계층<br>
전송계층은 연결형 통신을 가능하게 한다.
전송 계층의 연결형 프로토콜인 TCP는 두 호스트간에 정보를 주고 받기전에 연결을 수립함, 송수신간에 연결을 유지하다 끝나면 연결을 종료 할수 있음<br>
전송계층은 신뢰성 있는 통신을 가능하게 한다.
이 또한 TCP를 통해 가능하게 한다. 패킷이 수신지 까지 올바르게 전송되도록 재전송을 통한 오류 제어, 흐름제어, 혼잡 제어등 기능을 제공

앞서 언급한 바와 같이 항상 신뢰성 있는 연결이 가장 우선순위는 아니므로 비신뢰, 비연결형 통신을지원하는 UDP 프로토콜 또한 존재 하며 TCP 보다 빠른 전송이 가능하다

# 포트: 응용 계층과 연결 다리<br>
패킷이 실행중이 특정 애플리케이션 프로세스에 전달하기 위한 식별 정보
송신지와 수신지 포트를 통해 식별한다.<br>
포트번호는 16비트로 표현 가능하며 사용가능한 포트의 수는 2^16 개 (0번~65535번)<br>
TCP든 UDP든 상관없이 전송 계층(Transport Layer)에서 만들어지는 모든 데이터 덩어리에는 반드시 포트 번호가 들어간다.<br>
포트번호는 번호의 범위에 따라 세 종류로 분류된다
1. 잘 알려진 포트(0~1023):  시스템 포트라고도 하며 HTTP, HTTPS, DNS등 범용적으로 사용되는 애플리케이션 프로토콜이 사용<br>
2. 등록된 포트(1024~49151):흔히 사용되는 애플리케이션 프로토콜에 할당. MYsql db, Redis, OpenVPN<br>
3. 동적 포트번호(49152~65535): 사설, 임시 포트라고도 부름, 할당된 애플리케이션 프로토콜이 없어 자유롭게 사용 가능하다
   
서버로서 동작하는 프로그램은 주로, 잘알려진 또는 등록된 포트로 동작하는 경우가 많으며 클라이언트로 동작하는 프로그램은 동적 포트번호에서 임의로 할당되는 경우가 많다.<br>
서버는 '찾기 쉬운 고정 주소'가 필요하고, 클라이언트는 접속할 때 '잠시 빌려 쓰는 임시 주소'만 있으면 되기 때문<br>
192.168.0.15(IP주소):8000(포트번호)  와 같이 포트번호를 IP주소와 같이 쓰면 특정 호스트에서 실행중인 특정 애플리케이션 프로세스를 식별할 수 있다.

# 포트 기반 NAT<br>
NAT(Network Address Translation)은 사설 ip주소와 외부에서 사용하는 공인 ip주소를 변환 하는데 사용 <br>
이 변환을 위해 NAT 변환 테이블을 이용한다.

|**네트워크 내부 (사설 IP : 포트)**|**네트워크 외부 (공인 IP : 포트)**|
|---|---|
|192.168.0.10 : 50001|203.0.113.5 : 50001|
|192.168.0.11 : 50002|203.0.113.5 : 50002|
|192.168.0.12 : 50003|203.0.113.5 : 50003|

예시와 같이 공인 IP 하나에는 다수의 사설 IP가 대응된다.

왜?

1. 비용절감: 공인 IP는 통신사(ISP)로부터 비용을 지불하고 할당받는 제한된 자원 

2. 클라우드 아키텍처의 표준화: 현대의 클라우드 인프라(aws, gcp)는 거대한 사설 IP 망(VPC 등)으로 내부를 구축하고, 외부 인터넷과 통신이 필요한 서비스에만 공인 IP와 NAT 게이트웨이를 매핑해서 쓰는 아키텍처가 표준으로 쓰임 

NAPT

포트 기반의 NAT를 NAPT라 함(Network Address Port Translation)
포트를 활용해 하나의 공인 ip주소를 여러 사설 ip 주소가 공유할 수 있도록 하는 nat의 일종

# 포트 포워딩

**1. 문제 상황 (인바운드 통신의 한계)**
네트워크 외부에서 내부망의 특정 호스트(서버)로 먼저 통신을 시도할 때, 외부에서는 라우터의 '공인 IP'만 보인다. 라우터 입장에서는 외부에서 들어온 요청 패킷을 내부의 여러 사설 IP 중 어떤 기기에게 전달해야 할지 알 수 없으므로 연결을 차단(폐기)한다.

**2. 해결책 (포트 포워딩 설정)** 이를 해결하기 위해 **포트 포워딩**을 사용한다. 라우터에 규칙을 추가하여, 라우터의 '특정 외부 포트 번호'로 들어오는 트래픽을 내부 특정 호스트의 '사설 IP와 내부 포트 번호'로 자동 전달(매핑)하도록 설정하여 해결

**3. 통신 방식 (보안과 연결의 양립)** 이후 외부의 통신 주체에게는 내부 네트워크의 실제 정보(사설 IP)를 숨긴 채, '라우터의 공인 IP와 포워딩용으로 개방한 외부 포트 번호'만 알려주어 접속하게 한다. 라우터는 해당 외부 포트로 들어온 요청을 약속된 내부 호스트로 정확하게 토스(전달)한다.

| **외부 노출 (공인 IP : 외부 포트)** | **공유기의 포트 포워딩 규칙**                                         | **내부 실제 (사설 IP : 내부 포트)** |
| ------------------------- | ---------------------------------------------------------- | ------------------------- |
| `203.0.113.5 : 8080`      | `8080` 포트로 들어오면 $\rightarrow$ `192.168.0.10`의 `80` 포트로 넘겨라 | `192.168.0.10 : 80`       |
| `203.0.113.5 : 2222`      | `2222` 포트로 들어오면 $\rightarrow$ `192.168.0.11`의 `22` 포트로 넘겨라 | `192.168.0.11 : 22`       |

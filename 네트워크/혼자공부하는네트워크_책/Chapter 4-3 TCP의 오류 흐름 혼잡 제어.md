
# 오류 제어: 재전송 기법

재전송 상황
1. 중복된 ack 세그먼트를 수신했을 때
2. 타임아웃이 발생했을 떄: 재전송 타이머, 타임 아웃

RTT(Round Trip Time): 메세지 전송후 답변을 받을 때 까지의 시간

ARQ 재전송 기법
1. Stop-and-Wait ARQ: 수신 완료응답 받기 전에 새로운 메세지 X
2. Go-Back-N-ARQ: 전송 도중 잘못된 곳 부터 다시
3. Selective Repeat ARQ: 선택적으로 재전송(개별 확인 응답)

Pipelining: 연속해서 메세지 전송하는 기술
빠른 재전송: 세번의 동일한 ACK 세그먼트 수신시 곧바로 재전송


# 흐름제어: 슬라이딩 윈도우

수신버퍼: 수신된 세그먼트가 애플리케이션에 프로세스에 의해 읽히기 전에 임시로 저장되는 공간
버퍼 오버플로: 버퍼가 넘침<br>
흐름제어: 수신호스트의 처리 속도를 고려하며 송수신 속도를 균일하게 유지<br>
윈도우: 송신 호스트가 파이프라이닝 할수 있는 최대량


# 혼잡 제어

혼잡 윈도우: 혼잡 없이 전송할 수 있을법한 데이터양
혼잡제어알고리즘: 혼잡 제어 수행하는 방법<br>
AIMD(Additive Increase/Multiplicative Decrease): 혼잡감지x => 윈도우를 RTT마다 1씩 선형적으로 증가, 혼잡감지=> 혼잡 윈도우를 절반으로 떨어트리는 동작 반복

관련 알고리즘

1. Slow start: 혼잡 윈도우를 1부터 시작해 문제없이 수신된 ack 세그먼트 하나당 1씩 증가, RTT마다 2배씩증가

왜 1씩 증가인데 RTT마다 2배씩 증가?
```
### 1. 단계별 시뮬레이션 (윈도우 크기: CWND)

1. **시작 (CWND = 1):**
    
    - 송신 측이 **패킷 1개**를 보냅니다.
        
    - 잠시 후, 수신 측으로부터 **ACK 1개**가 도착합니다.
        
    - **규칙 적용:** ACK 1개를 받았으니 CWND를 **1 증가**시킵니다.
        
    - 결과: CWND는 1 + 1 = 2가 됩니다. (1 RTT 경과)
        
2. **다음 단계 (CWND = 2):**
    
    - 이제 윈도우가 2이므로, **패킷 2개**를 연속해서 보냅니다.
        
    - 잠시 후, **ACK 2개**가 각각 도착하겠죠?
        
    - **규칙 적용:**
        
        - 첫 번째 ACK 도착 → CWND 1 증가 (2->3)
            
        - 두 번째 ACK 도착 → CWND 1 증가 (3->4)
            
    - 결과: CWND는 4가 됩니다. (2 RTT 경과)
        
3. **그다음 단계 (CWND = 4):**
    
    - 이제 **패킷 4개**를 보냅니다.
        
    - **ACK 4개**가 도착할 것입니다.
        
    - **규칙 적용:** ACK가 4번 올 때마다 CWND를 1씩 총 4번 늘립니다.
        
    - 결과: CWND는 4 + 4 = 8이 됩니다. (3 RTT 경과)
```

느린시작 임계치(Slow start threshold): 혼잡 윈도우가 증가하다 느린 시작 임계치 이상이 되거나 타임아웃 발생, 세번의 중복된 ack 세그먼트가 발생하면 아래 세가지 방법 선택

1. 타임아웃 발생: 혼잡 윈도우값을 1, 느린시작 임계치를 혼잡이 감지되었을 시점의 혼잡 윈도우 값의 절반값으로 초기화한뒤 느린 시작 재개<br>
2. 혼잡 윈도우>=느린시작임계치: 느린시작 종료 혼잡 회피
3. 세번의 중복 ack 발생: (빠른재전송후) 빠른 회복 수행<br>

혼잡회피 알고리즘: rtt마다 혼잡 윈도우를 1mss(maximum segment size)씩 증가<br>
빠른 회복 알고리즘: 느린 시작은 건너뛰고 혼잡 회피를 수행

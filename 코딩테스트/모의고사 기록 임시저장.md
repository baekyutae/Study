## 1번. 신고 결과 받기

### 제출한 코드

```python
'''
각유저가 여러명의 유저를 신고가능
한사람에 대해 여러번 신고도 가능하지만 횟수는 1회로 처리
k번 이상 신고하면 정지당하고, 정지 당한 유저를 신고한 유저에게 메일이 발송됨

유저 목록을 담은 문자배열 id_list, 이용자 id와 신고한 id를 공백으로 연결한 문자배열 report, k가 매개 변수로 주어짐

id_list에 담긴 순서로 각 유저가 받은 메일숫자를 담은 정수 배열을 결과로 반환 하는 함수를 구현해라

def solution(id_list, report, k):
    1. 누가 정지 대상인지
    2. 유저중 정지 대상을 신고한 사람은 누구고, 정지대상중 몇명을 신고했는지

    {이름:신고당한 횟수}
    이중에서 k 이상으로 신고당한 사람을 추려 정지 대상 목록 뽑아
    정지대상자 목록 ["이름1","이름2"]
    
    {이름:[신고한 당한 사람1,신고당한 사람2]}
    여기서 신고한 당한 사람이 정지 대상자 목록에 몇개 있느냐에 따라 메일수 +=1
    
    result = []
    
    return result
'''


def solution(id_list, report, k):
    result = [0]*len(id_list)
    reportCount = {}
    name_Reportmember = {}
    banList = set()
    
    for rp in report:
        i, j = rp.split(' ')
        if j not in reportCount:
            reportCount[j] = 1
            
        else:
            reportCount[j] += 1
            if reportCount[j] >= k:
                banList.add(j)
            
        if i not in name_Reportmember:
            name_Reportmember[i] = [j]
        
        else:
            if j not in name_Reportmember[i]:
                name_Reportmember[i].append(j)
    
    idxMap = {}
    for idx, name in enumerate(id_list):
        idxMap[name] = idx
        
    for name, rpm in name_Reportmember.items():
        for n in rpm:
            if n in banList:
                # print(rpm)
                result[idxMap[name]] += 1
    
    
    print(reportCount)
    print(name_Reportmember)
    print(banList)
    
    return result
```

실행 결과: 예시 1번 통과, 예시 2번 실패 (`["ryan con"] × 4`, k=3에서 기댓값 `[0,0]`, 실제 `[0,1]`)

### 해설

- **틀린 이유**: "같은 사람을 여러 번 신고해도 1회" 조건이 `name_Reportmember`에는 적용됐지만 `reportCount`에는 빠졌다. `"ryan con"`이 4번 들어오면 `reportCount["con"] = 4`가 되어 정지 대상이 된다.
- **숨은 버그**: `banList`에 넣는 코드가 `else` 안에만 있다. 그래서 k=1이면 첫 신고 때 정지 목록에 들어가지 않는다.
  - 반례: `id_list=["a","b"]`, `report=["a b"]`, `k=1` → 정답 `[1,0]`, 이 코드 `[0,0]`
- **느려질 수 있는 부분**: 신고한 사람 목록을 리스트로 두고 `j not in 리스트`로 검사해서, 입력이 크면 느려질 수 있다. 집합(set)을 쓰면 된다.
- **메모에 적은 1·2단계 설계 자체는 맞았다.**

### 정답 코드

```python
def solution(id_list, report, k):
    report = set(report)  # 같은 사람을 여러 번 신고해도 1회로 처리

    # 1. 사람별로 신고당한 횟수를 센다
    reportCount = {name: 0 for name in id_list}
    for rp in report:
        _, reported = rp.split()
        reportCount[reported] += 1

    # 2. 다 센 뒤에 정지 대상을 한 번에 판정한다
    banList = {name for name, cnt in reportCount.items() if cnt >= k}

    # 3. 정지 대상을 신고한 사람에게 메일 1통씩
    mail = {name: 0 for name in id_list}
    for rp in report:
        reporter, reported = rp.split()
        if reported in banList:
            mail[reporter] += 1

    return [mail[name] for name in id_list]
```

- 시간 복잡도: O(신고 수 + 유저 수)
- 다음에 알아볼 단서: 지문에 "여러 번 해도 1회"가 나오면 입력부터 중복 제거한다. 개수는 도중에 판정하지 말고 다 센 뒤에 판정한다.
- 유형: 구현(지문 조건을 빠짐없이 코드로 옮기기)이 핵심이고, 해시·집합은 도구다.

## 2번. 미로 탈출

### 제출한 코드

```python
'''
최단 경로를 두번 나눠서 찾기
레버 까지 가는 최소 거리
레버에서 출구까지 가는 최소 거리

시작지점, 레버, 탈출구 셋중 하나라도 벽으로 막혀 접근이 안되면 -1  반환

최단 경로니 bfs?

'''
from collections import deque
def solution(maps):
    dx = [-1, 1, 0, 0]
    dy = [0, 0, -1, 1]
    row = len(maps)
    col = len(maps)
    visited1 = set()
    visited2 = set()
    # 레버로 가는 최단 거리부터 탐색
    queue1 = deque()
    queue2 = deque()
    #시작 지점 및 레버 탐색
    for r in range(row):
        for c in range(col):
            if maps[r][c] == "S":
                queue1.append((r,c))
            if maps[r][c] == "L":
                queue2.append((r,c))
    # 레버까지 도달하는 최단시간
    lTime = 0
    while queue1:
        r,c = queue1.pop()
        # 레버를 찾았다면 종료
        if maps[r][c] == "L":
            break
        # 상하 좌우 한칸씩 이동할수 있는 좌표를 탐색
        # maps 밖이 아니고, 벽이 아니면 queue에 추가
        # queue에 추가가 되었다면 lTime을 1 증가
        for i in range(4):
            new_r = r+dx[i]
            new_c = c+dy[i]
            if 0<=new_r<row and 0<=new_c<col and maps[new_r][new_c] != "X" and (new_r,new_c) not in visited1:
                queue1.append((r,c))
                visited1.add((r,c))
                lTime+=1
    # 이제 레버에서 출구 까지 최단거리 탐색 
    eTime = 0
    while queue2:
        r,c = queue2.pop()
        # 탈출구
        if maps[r][c] == "E":
            break
        # 상하 좌우 한칸씩 이동할수 있는 좌표를 탐색
        # maps 밖이 아니고, 벽이 아니면 queue에 추가
        # queue에 추가가 되었다면 eTime을 1 증가
        for i in range(4):
            new_r = r+dx[i]
            new_c = c+dy[i]
            if 0<=new_r<row and 0<=new_c<col and maps[new_r][new_c] != "X" and (new_r,new_c) not in visited1:
                queue2.append((new_r,new_c))
                visited2.add((new_r,new_c))
                eTime+=1   
    if lTime == 0 or eTime == 0:
        return -1
    
    else:
        return lTime+eTime
```

실행 결과: 실행 시간 10초 초과

### 해설

방향은 맞았다. 레버까지 한 번, 레버에서 출구까지 한 번으로 최단 경로를 나누고, 최단 거리를 BFS로 구하는 것이 정답 풀이다. 구현에서 여러 곳이 동시에 틀렸다.

| 위치 | 문제 | 결과 |
| --- | --- | --- |
| `queue1.append((r,c))` | 이웃 칸이 아니라 **현재 칸**을 다시 넣음. `visited1`에도 현재 칸을 넣어서 이웃 검사는 계속 통과함 | 같은 칸이 끝없이 큐에 들어감 → **시간 초과의 직접 원인** |
| `queue.pop()` | 오른쪽에서 꺼내서 스택처럼 동작함. BFS는 `popleft()` | 최단 거리가 보장되지 않음 |
| `lTime += 1` | 큐에 넣은 칸 수를 셈. 거리가 아님 | 무한 루프를 고쳐도 탐색한 칸 수가 답으로 나옴 |
| `col = len(maps)` | 행 수를 열 수로 씀. `len(maps[0])`이어야 함 | 직사각형 지도에서 범위가 틀림 |
| 두 번째 BFS의 `visited1` | 복사해 붙여 넣으면서 `visited2`로 안 바꿈 | 레버 → 출구 탐색이 오염됨 |
| `lTime == 0`이면 -1 | 도달하지 못해도 탐색한 칸이 있으면 0이 아님 | 도달할 수 없는 경우를 못 잡음 |

**핵심**: 거리는 "전체 카운터 하나"가 아니라 **칸마다 붙는 값**이다.

### 권장 풀이 (의사코드)

```text
bfs(시작, 목표):
    큐에 (시작, 0) 넣고 시작 칸 방문 표시
    큐가 빌 때까지:
        (칸, 거리) = 왼쪽에서 꺼냄
        칸이 목표면 거리를 반환
        상하좌우 이웃 중 범위 안이고, 벽이 아니고, 방문하지 않은 칸:
            방문 표시 후 (이웃, 거리+1)을 넣음
    목표에 못 갔으면 -1 반환

a = bfs(S, L),  b = bfs(L, E)
둘 중 하나라도 -1이면 -1, 아니면 a + b
```

- BFS를 함수 하나로 만들어 두 번 부르면 복사·붙여넣기 버그(`visited1`)가 생기지 않는다.
- 시간 복잡도: O(행 × 열) × 2
- 다음에 알아볼 단서: 최단 거리 BFS는 거리를 칸마다 따라다니게 한다(튜플로 같이 넣거나 dist 배열). 큐에 넣을 때 방문 표시하고, 넣는 대상은 이웃 칸이다.
- 같은 실수가 6월 Average of Levels에서도 있었다(`pop` 사용, 꺼낸 노드가 아니라 `root` 기준 처리).

실행 결과: `IndentationError: unexpected indent`

### 해설

- **한 명씩 따라가는 방식으로는 효율성 테스트를 통과할 수 없다.** 돌은 최대 20만 개, 돌에 적힌 수는 최대 2억이다. 사람이 최대 2억 명까지 나올 수 있고 한 사람을 따라가는 데 돌 20만 개를 본다.
- 지문을 잘못 읽은 부분: 출발점과 도착점은 돌 밖의 강둑이다. 코드는 첫 번째 돌(`loc=0`) 위에서 출발한다.

**관찰**
1. 사람은 항상 가장 가까운, 0이 아닌 돌을 밟는다. 그래서 p명이 지나가면 모든 돌은 `max(원래 값 - p, 0)`이 된다. 한 명씩 따라갈 필요가 없다.
2. m번째 사람이 건널 때 값이 m보다 작은 돌은 전부 0이다. 그런 돌이 **k개 연속**이면 m번째 사람은 못 건넌다.
3. m명이 건널 수 있으면 m-1명도 건널 수 있다. 그래서 사람 수 m을 이분탐색할 수 있다.

```text
    각 돌 s에 대해:
        s < m 이면 run += 1, run이 k 이상이면 False
        아니면 run = 0
    True

건널수있나(m)이 참인 가장 큰 m을 이분탐색으로 찾아 반환
```

- 시간 복잡도: O(돌 개수 × log(최대값))
- 다른 풀이: 크기 k 구간마다 최댓값을 구하고 그중 최솟값이 답이다(덱으로 O(돌 개수)).
- 다음에 알아볼 단서: 입국심사·Koko와 같은 구조다. 답(사람 수, 속도, 용량)의 범위가 수억 단위라 하나씩 해 볼 수 없고, "답이 m이면 m보다 작은 값도 된다"는 성질이 있으면 답을 이분탐색할 수 있는지부터 의심한다.
- 같은 구조의 이전 문제: 무지의 먹방 라이브(1월, 1초 단위 시뮬레이션 → 한꺼번에 계산).

이렇게행열 뒤집힌 지도를 따로 만들지 말고 count 하나로 표현할수 있단것도 복기에 기록해둬야겠음

## 해설

### 핵심 유형

구현(시뮬레이션). 모든 두 사람 쌍에 규칙을 한 번씩 적용해 이긴 사람에게 +1을 한다. 필요한 자료는 두 가지다.

- `count[i][j]`: i가 j에게 준 선물 수를 담은 N×N 표. 행은 준 사람, 열은 받은 사람이다.
- 사람별 선물지수: 준 총합 − 받은 총합

친구 수 N이 50 이하라 모든 쌍을 직접 비교해도 충분하다.

### 권장 풀이

```python
def solution(friends, gifts):
    n = len(friends)
    idx = {name: i for i, name in enumerate(friends)}
    count = [[0] * n for _ in range(n)]
    gift_index = [0] * n
    for g in gifts:
        a, b = g.split()
        count[idx[a]][idx[b]] += 1
        gift_index[idx[a]] += 1   # 선물지수를 입력 읽을 때 미리 계산
        gift_index[idx[b]] -= 1
    receive = [0] * n
    for i in range(n):
        for j in range(i + 1, n):
            if count[i][j] > count[j][i]:
                receive[i] += 1
            elif count[i][j] < count[j][i]:
                receive[j] += 1
            elif gift_index[i] > gift_index[j]:
                receive[i] += 1
            elif gift_index[i] < gift_index[j]:
                receive[j] += 1
    return max(receive)
```

- `giftMap`은 `count`의 행, `refundMap`은 `count`의 열과 같다. 표 하나로 두 방향을 모두 꺼낼 수 있다.
- 동점일 때 특수값을 돌려주는 함수를 두지 않고 `elif` 분기로 끝내면 KeyError가 생기지 않는다.

### 복잡도

N = 친구 수(≤ 50), G = 선물 기록 수(≤ 10,000)

- 작성한 코드: O(G + N³). 쌍마다 `giftIdx` 안에서 `sum`을 다시 계산한다. N = 50이면 약 12.5만 번이라 통과에는 문제없다.
- 권장 풀이: O(G + N²). 선물지수는 쌍마다 바뀌지 않으므로 한 번만 계산한다.

### 자주 틀리는 지점

1. `for a in friends: for b in friends`로 돌면 (a, b)와 (b, a)를 모두 처리해 결과가 정확히 2배가 된다. 안쪽 반복을 `i + 1`부터 시작하면 쌍이 항상 (작은 인덱스, 큰 인덱스) 순서로 한 번씩만 나온다.
2. 이름을 돌려주는 함수가 동점일 때 `0`을 돌려주면 호출하는 쪽에서 `fIdx[0]` KeyError가 난다. 특수값은 `None`으로 두고 호출하는 쪽에서 확인한다.
3. 비교 블록이 안쪽 `for` 밖으로 들여쓰기되면 마지막 쌍만 처리된다.
4. 2차원 리스트는 `[[0] * n for _ in range(n)]`로 만든다. `[[0] * n] * n`은 같은 리스트 하나를 n번 참조하므로 한 칸을 바꾸면 모든 행이 함께 바뀐다.

### 다음에 알아볼 단서

- "두 명끼리 비교해 한쪽에 점수를 준다"는 문장이 보이면 순서 없는 쌍이다. `i < j`로 한 번씩만 도는지부터 정한다.
- "A가 B에게 몇 번" 같은 방향 있는 개수가 필요하면 이름→인덱스 사전과 N×N 표를 먼저 떠올린다.
- 사람별로 쌍과 무관하게 정해지는 값(선물지수)은 입력을 읽을 때 미리 계산한다.
- 자료 형태가 안 떠오르면 필요한 값을 꺼내는 식을 `=` 오른쪽 코드로 먼저 써 본다.
